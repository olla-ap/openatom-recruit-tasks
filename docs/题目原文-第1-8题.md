## 1、环境搭建与程序运行

📝 **题干**：在真实企业级开发中，配置本地开发环境并理解多文件项目的组织结构是第一步。请完成基础环境搭建，并编写你的第一个多类协同运行的 Java 程序。

💡 **行业前沿贴士**：在最新的 Java 25 预览版中，官方引入了极简版的无名类和 void main() 写法以降低新手门槛。但在本任务中，为了与真实的企业工程代码接轨，我们依然要求掌握最经典的传统写法。

🎯 **要求**：

- **Task2**：创建主类 HelloWorld，使用经典的 `public static void main(String[] args)` 方法，在控制台中打印出 `Hello world`。
- **Task3**：新建 GreetingService 类，提供带有字符串参数的 `public void sayHello(String name)` 方法。在主方法中实例化该类并调用，并在控制台打印出 `Hello!`。

🧠 **考察能力**：JDK 环境配置、IDE 基本使用、经典多文件类调用，以及对 Java 版本迭代极简演进的认知。

## 4.1、📦 面向对象上篇：封装、构造与静态成员

📝 **题干**：面向对象（OOP）是 Java 的核心灵魂。在智能仓储系统中，每个商品都是一个独立的对象，但系统也需要统计整体的商品创建数量。请你利用封装特性设计商品类，并清晰区分实例成员与静态成员的使用场景。

🎯 **要求**：

- **Task1**：创建一个 Product 类。使用 private 访问修饰符隐藏属性：商品编号（String）、名称（String）和价格（double）。并提供配套的 public Getter/Setter 方法以保护数据安全性。
- **Task2**：编写方法的重载：提供一个无参构造器，以及一个包含全部三个属性的全参构造器。

- **Task4**：在 main 方法中实例化两个不同的 Product 对象，调用实例方法打印其信息，最后通过类名调用静态方法，打印系统总共创建的商品对象数量。

🧠 **考察能力**：类的定义、对象的实例化、访问修饰符（public/private）的权限控制隔离、构造器重载、以及对实例属性（归属具体对象）与静态属性（归属类本身）的区别认知。

## 4.4、💡 终极 Boss 战：手写迷你 ArrayList（动态数组）

📝 **题干**：普通的数组长度固定，在处理动态增长的物流订单时非常不便。虽然我们还没正式学习 Java 强大的集合框架，但你已经完全具备了手写它的能力！请运用刚学过的面向对象与泛型知识，利用底层定长数组，自己动手封装一个可以"自动扩容"的动态数组类。

🎯 **要求**：

- **Task1**：核心结构搭建。创建一个泛型类 `MyArrayList<T>`。内部封装一个对象数组 `private Object[] elements` 用于存储数据，以及一个 `private int size` 用于记录实际存储的元素个数。提供无参构造器，将底层数组初始长度设为 3（故意设小以便测试扩容）。
- **Task2**：实现添加与扩容 `public void add(T element)`。每次添加前检查，如果 size 等于 elements.length（底层数组已满），则创建一个长度为原来 2 倍 的新数组，将老数组的数据全部复制过去，最后将 elements 引用指向新数组。扩容完成后（或未满时），将新元素存入 `elements[size]`，并让 `size++`。
- **Task3**：实现查询 `public T get(int index)`。首先进行边界安全检查（如果 index < 0 或 index >= size 则打印报错并返回 null）。验证通过后，返回对应位置的元素（需向下转型为 (T)）。
- **Task4**：实现删除 `public void remove(int index)`。边界检查通过后，核心逻辑是移位：使用一个 for 循环，将 index 之后的所有元素依次向前移动一位（即 `elements[i] = elements[i+1]`）。最后将多余的最末尾元素置为 null，并 `size--`。
- **Task5**：实战测试。在 main 方法中实例化 `MyArrayList<String>`。连续存入 5 个包裹单号（此时必然触发扩容机制）。打印获取索引为 2 的单号；接着删除索引为 1 的单号，并再次打印索引为 1 的单号验证数据是否成功前移。

🧠 **考察能力**：数组的深度操作（遍历、复制、内存移位）、封装与泛型的综合实战、以及体会集合底层"空间换时间"的动态扩容架构思维⚙️。

**示例输出**：

```
成功添加：单号A
成功添加：单号B
成功添加：单号C
触发底层扩容！当前数组容量由 3 扩容至 6
成功添加：单号D
成功添加：单号E
获取索引[2]的元素：单号C
删除了索引[1]的元素(单号B)
验证移位，此时索引[1]的元素变为了：单号C
```

## 4.5、🏗️ 面向对象进阶：经典设计模式启蒙

📝 **题干**：真正的企业级开发不仅要求代码能跑，还要求代码优雅、可维护。在我们的智能物流系统中，为了节省内存，系统的"全局配置中心"只能存在一个实例；为了解耦，我们需要一个"车辆调度工厂"来分配交通工具；同时，一个复杂的"物流运单"包含几十个选填参数。请你运用单例、工厂和建造者模式来重构这些模块。

🎯 **要求**：

- **Task1**：独一无二的调度中心（单例模式 Singleton）
  - 创建一个 LogisticsConfig 类，内部包含一个属性 `private String systemName = "顺风智能仓储系统"`。
  - 核心步骤：私有化无参构造器（防止外部 new 对象）；在类内部创建一个静态的私有实例；提供一个 `public static LogisticsConfig getInstance()` 方法返回该实例。
  - 在 main 方法中获取两个实例，并使用 `==` 比较它们是否为同一个内存地址。
- **Task2**：智能车辆调度（简单工厂模式 Simple Factory）
  - 回顾中篇里的 TransportVehicle（包含卡车和无人机）。
  - 创建一个 VehicleFactory 类，提供一个静态方法 `public static TransportVehicle createVehicle(String type)`。
  - 如果传入 "Truck"，则 new 一个卡车并返回；传入 "Drone"，则返回无人机；传入其他则返回 null。
  - 在 main 方法中，不直接 new 卡车，而是让工厂为你生产一辆，并调用其计费方法。
- **Task3**：优雅的复杂对象组装（建造者模式 Builder）
  - 创建一个物流订单类 LogisticsOrder，包含属性：订单号、寄件人、收件人、是否易碎、保价金额（其中只有订单号是必填的，其他全为选填）。
  - 在该类内部，创建一个静态内部类 Builder。Builder 包含同样的属性，并为每个选填属性提供赋值方法，赋值后返回 Builder 对象自身（`return this;`），以便进行链式调用。
  - 提供一个 `build()` 方法，将 Builder 中的数据赋给 LogisticsOrder 并返回。
  - 在 main 方法中，使用链式编程语法创建一个易碎且保价的物流订单并打印。

🧠 **考察能力**：

- 单例模式：对 private 构造器与 static 变量的极致利用。
- 工厂模式：面向接口/抽象类编程的思想，体会"创建与使用分离"的解耦之美。
- 建造者模式：静态内部类的运用，以及 `return this;` 链式编程（Fluent API）的优雅体验。

**示例输出**：

```
单例测试：配置类实例A与实例B是否相同？ -> true
工厂调度：工厂成功分配 -> 🚁无人机 [D-007]，计费启动...
运单生成：订单号[OD-999], 寄件人[Alice], 收件人[Bob], 易碎品[true], 保价[1000.0元]
```

## 5、异常和异常处理

📝 **题干**：在真实业务开发中，异常不仅用来报错，还要携带业务数据（如订单号），并且需要对底层系统异常进行包装，以保护系统内部结构不会暴露。请你编写 Java 代码，实现一个简单的支付网关并妥善处理各种异常场景。

🎯 **要求**：

**Task1**：

- 自定义一个受检异常 InsufficientFundsException，要求包含一个额外的 String 类型属性 transactionId（交易流水号），并提供相应的构造方法初始化信息和流水号以及 getter 方法。
- 自定义一个非受检异常 SystemMaintenanceException，该异常支持异常链，并提供构造方法。

**Task2**：

创建支付类 PaymentProcessor，包含一个支付方法，接收参数为金额和流水号：

- 如果金额 < 0，该方法抛出 java 原生的 IllegalArgumentException，提示"支付金额不能为负数"
- 如果金额 > 10000，抛出自定义的 InsufficientFundsException，提示"余额不足"，并传入参数中的流水号
- 如果金额 = 500，抛出自定义的 SystemMaintenanceException，提示"网络连接超时"，并将一个 NullPointerException 原始异常附带进去
- 其他情况则打印"交易[流水号]支付成功，金额：[金额]"

**Task3**：

创建服务类，包含一个方法，该方法中需实例化支付类并进行异常捕获：

- 捕获受检异常，打印"余额不足，流水号为[流水号]"，并返回 false
- 捕获 IllegalArgumentException，需将其包装 SystemMaintenanceException 重新抛出
- 捕获其他异常，打印"发生未知异常:[异常信息]"，并返回 false
- 无论支付是否成功，最后都需要打印"执行资源清理任务..."
- 没有异常，返回 true

**Task4**：

编写 main 方法，测试 <0、>10000、=500、以及正常支付四种情况，并做出适当的捕获打印，以免程序直接崩溃。

🧠 **考察能力**：自定义异常，异常链，多重 catch 的应用，try-catch-finally 的执行逻辑。

## 6、集合运用

📝 **题干**：在日常业务开发中，我们经常需要对批量数据进行清洗、去重、分组统计和排序。Java 提供的丰富集合框架是解决这些问题的利器。请你学习 java 中的集合，并实现一个简单的电商订单分析器。

🎯 **要求**：

**Task1**：

- 创建实体类 Order，包含属性为订单号、客户姓名、订单金额、商品标签（属性为 `List<String>`）
- 实现排序规则：默认按订单金额降序排列，如果金额相同按订单号升序排列

**Task2**：

创建 OrderAnalyzer 类，内部维护一个 `List<Order>` 存储所有订单，包含以下方法：

- `public void add(Order order)`：加入订单
- `public void removeInvalidOrders()`：将所有金额小于等于 0 的订单删除
- `public Set<String> getAllUniqueTags()`：返回包含所有标签（需要去重）的集合
- `public Map<String,Double> getCustomerSpendMap()`：返回的 Map 中，Key 为客户姓名，Value 为该客户所有订单金额总和
- `public List<Order> sortOrdersByCustomerName()`：返回一个新的 list 集合中，按客户姓名进行字母顺序升序排列

**Task3**：

在 main 方法中实例化 OrderAnalyzer，调用各个方法，测试以下数据：

- 订单1："O001", "Alice", 150.0, ["电子", "数码"]
- 订单2："O002", "Bob", -50.0, ["服装"]
- 订单3："O003", "Alice", 200.0, ["图书", "电子"]
- 订单4："O004", "Charlie", 200.0, ["生鲜"]
- 订单5："O005", "Bob", 300.0, ["服装", "户外"]

## 7、文件操作

📝 **题干**：在处理大文件网络传输时，由于网络不稳定或内存限制，可能需要将大文件切割成一个个小的分片，分别传输到目的地后，再将这些小分片还原成原始文件。请你运用 I/O 技术，实现本地文件的分片与合并功能。

🎯 **要求**：

**Task1**：

- 编写文件分片方法，输入参数：源文件路径 sourceFilePath、分片输出目录路径 outputDirPath、每个分片最大大小 chunkSize（单位：字节）
- 将源文件按 chunkSize 切割为多个子文件，存放到 outputDirPath 目录下。子文件命名规则为源文件名.partX（X 从 1 开始递增），如源文件为 myWords.txt，分片应为 myWords.txt.part1...
- 需要使用缓冲区进行读写，注意最后一次读取的字节数

**Task2**：

- 编写文件合并方法，输入参数：分片所在目录 targetDirPath、原始文件名 originalFileName、最终合并后的输出文件路径 mergedFilePath。
- 解析出分片的后缀数字 X，按照 X 的大小进行排序，依次读取文件内容追加写入到最终文件中
- 合并完成后，自动删除所有 .partX 文件

**Task3**：

使用文件测试以上方法，大文件至少要能切分为 3 个分片，并验证源文件与合并后文件的一致性。

🧠 **考察能力**：字节流的运用，文件排序的逻辑处理。

## 8、线程同步

📝 **题干**：一家网红奶茶店中有 2 名店员和 2 名顾客，每个店员做完 10 杯奶茶后直接下班，每个顾客喝完 10 杯奶茶后才会满足，且吧台上最多只能放 5 杯奶茶。

🎯 **要求**：

**Task1**：

- 编写吧台类作为奶茶的容器
- 该类提供 put 方法，如果吧台未满，则接收店员制作的奶茶，打印"[店员名]制作了[奶茶]，吧台当前数量：[奶茶数量]"
- 该类提供 take 方法，如果吧台有奶茶，则允许顾客取走，打印"[顾客名]取走了[奶茶]，吧台剩余数量：[奶茶数量]"

**Task2**：

- 编写店员类，实现 Runnable 接口，在 run 方法中循环制作奶茶
- 调用 `Thread.sleep()` 模拟制作时间

**Task3**：

- 编写顾客类，实现 Runnable 接口，在 run 方法中循环取走奶茶
- 调用 `Thread.sleep()` 模拟喝奶茶时间

**Task4**：

在 main 方法中进行测试，确保吧台上奶茶数量不超过 5 且不低于 0，每个店员都下班且每个顾客都得到满足。

🧠 **考察能力**：对多线程模型的理解，`wait()` 和 `notifyAll()` 等的运用。
